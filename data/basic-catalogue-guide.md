# 基础身份库网页管理

打开 `minimal-adv-rpg.html`，点击作品名编辑名称、首发年份、厂商、主要玩法、剧情风格和来源。手机端以卡片显示。年份可以手填或选择建议，未知留空；支持1970年至当前年份后10年。作品特征在主要玩法之后，按九个维度组织。同一维度可多选，每部总计最多六个标签，可留空。叙事视角描述故事的讲述方式，与游戏镜头和操作视角分开。

## 分页与筛选（2026-11-06）

结果上方、下方均可输入具体页码，按 Enter 或点击“跳转”；页码必须为当前筛选结果范围内的正整数。更换筛选会回到第一页，两处页码同步，空结果停用跳转。

厂商名搜索覆盖完整目录，不区分大小写或全半角。厂商下拉框合并仅大小写／空白不同的选项并显示作品数量，默认列出200个高覆盖厂商；输入名称即可查找其他厂商，已选项保留可见。厂商名搜索也直接筛选作品，地区、具体厂商、年份、玩法及风格可以组合查询。

地区提供日本厂商、非日本厂商和地区待核。`basic-manufacturer-regions.json` 是独立显示索引，先登记既有具名厂商专题、名称表及部分官方资料支持的主体。未登记或资料冲突的地区保持待核；不按文字、作品语言、来源网站或母公司所在地猜测。来源别名不因地区相同合并为同一厂商；历史开发、发行与实体身份不变。

作品特征筛选使用九维词表。原三列中可以唯一归类的值已迁入对应维度。当前有一部作品的三个旧值同属内容提示，移出检索，原值在编辑窗口保留作历史参考。旧格式导入仍可读取。

玩法筛选合并中英文近义类别，并索引关联档案已明确编目的图文表现和操作方式。复合玩法按各组成类别分别命中。菜单指令、选项分支、文字输入分别保留，互动小说不自动等同解析器。标为普通 RPG 的作品可用“纯RPG”排除，已明确标为剧情 RPG 或混合玩法的记录单独处理。显示分类不改写原始玩法字段。

## 组合与高级检索

可用首发年份区间、多选玩法、作品特征和厂商地区快速缩小范围。每组高级条件内采用 AND，多个条件组采用 OR，每行的多个值可设为任一、全部或排除。可点击“载入 1980—1999 年示例”组合文字／图形冒险、题材、制作地区与排除项。范围填写 `1980..1999`，也可使用 `>= 2` 一类比较写法。

高级字段沿用关联档案的角色、创作署名、叙事定位、平台发行及内容身份。IFDB 来源快照按 TUID 关联系列，VNDB 来源快照按 vID 关联语言与平均游玩分钟。发行地区使用逐条核对的发行 ID 索引，沿用相应发行的来源。制作地区基于有地区登记的制作主体，厂商关联、语言与发行地区分别处理。多个正向发行条件须落在同一条发行记录；排除条件可剔除存在对应发行的作品。缺字段不会命中正向条件，内容版本数量只统计已编目原作和增补，不按发行平台累计。高级索引按需加载。

## 保存、删除与撤销

“连接写入权限”使用本仓库 `wt1234-donkey/visual-novel` 的 Fine-grained personal access token，授权 Contents: Read and write。凭证仅存在当前页面内存，不放入浏览器存储、导出文件或提交内容。保存前重新读取并检查记录，冲突时保留表单输入并停止写入；点击“重新读取网站修改”后核对再保存。

修改保存到 `data/basic-catalogue-edits.json`，与历史来源数据共同构成当前基础库。基础库、作品发现的基础库结果和批量补录主库窗口均应用该文件；原始采集文件仍供溯源，不代表已应用网页修改的有效数据。保存成功后本页立即更新，其他设备在 Pages 发布完成后刷新可见。连接窗口可依次撤销最近3次操作，包括整批导入、删除和合并。删除有关联版本的主作品前须先解除版本合并。

## 固定格式导入

使用页面的 CSV 或 JSON 模板，删除示例后填写真实作品。每次1至500部，文件不超过5MB；全部校验通过后预览，点击“确认导入”才写入。无自动部分导入；重名同年记录会停止整批写入，请先编辑已有作品或核实后合并。

CSV必须为UTF-8编码，表头按顺序保留：

`名称,年份,厂商,主要玩法,剧情基调,情绪体验,叙事表达,人物关系,故事题材,内容提示,叙事视角,叙事结构,故事背景,来源`

名称、厂商、主要玩法必填；厂商和玩法未知时明确填“厂商待核”“玩法待核”。年份未知留空。维度可留空。同一格的多个标签用顿号「、」分隔，每部合计最多六个。旧版三列和六维模板仍可导入。来源可留空，填写时须为HTTP或HTTPS网址。含逗号、换行或引号的值用双引号包围，内部双引号写成两个双引号。Excel编辑后选择“CSV UTF-8”保存。

JSON 为作品数组，每条含 `title`、`firstYear`、`group`、`gameplay`、`plotStyles`、`source`，并可包含 `plotTags`。新模板的 `plotStyles` 为留给旧数据的空数组，`plotTags` 按需填写 `tone`、`emotion`、`expression`、`relationship`、`theme`、`content`、`perspective`、`structure`、`setting`。单个标签可用字符串，同维度多个标签用字符串数组。未知年份用 `null`，未知来源用空字符串。

## 批量编辑标签

先筛选和勾选作品，可以勾选当前页，或在筛选结果为 1 至 500 部时勾选全部结果。选择“批量编辑标签”后，可追加标签、仅补充空白维度、替换选中维度、删除指定标签或清空全部特征标签。除清空外，留空的维度不参与更新。每批先预览修改前后，再连接 GitHub 并确认写入。每批为一次撤销操作。

## CSV 更新已有作品

打开“CSV 更新标签”可下载 [CSV 空白模板](../templates/basic-style-update.csv) 或 [CSV 填写示例](../templates/basic-style-update-example.csv)，也可导出所选作品的更新模板。正式更新前请替换示例行。CSV 用 UTF-8 编码，每批 1 至 500 部，表头保持如下顺序。

`作品ID,作品名称,剧情基调,情绪体验,叙事表达,人物关系,故事题材,内容提示,叙事视角,叙事结构,故事背景`

作品 ID 用于精确匹配。作品名可留空，填写时须与当前名称一致。维度列留空时保留现值，填写“清空”移除该维度全部标签；填写一个或多个标签时替换该维度现值，多项用顿号「、」分隔。合并其他维度后每部最多六个，超限整批停止。重复 ID、无效 ID、名称不匹配或标签维度错误会停止整批写入。遇到并发修改时，重新读取基础库后重新预览。

## AI 标签候选

1. 在基础库勾选作品，打开“AI 标签候选审核”，下载 `basic-style-request.json`。系统按基础作品 ID 或已有主库关联 ID 匹配完整档案及网页修订，取已有剧情简介和可追溯来源，按作品剩余标签额度生成请求，已有标签从候选中排除。资料不足的作品进入待补资料清单。
2. 在装有 Node.js 20+ 和正在运行的 Ollama 的电脑上，从仓库根目录运行以下命令。第三个参数改为 `ollama list` 显示的本机模型名。首次可先试选少量作品。

   ```sh
   node scripts/suggest_basic_styles.mjs basic-style-request.json basic-style-candidates.json qwen2.5-vl
   ```

3. 导入生成的 `basic-style-candidates.json`。手动整理时，可下载 [候选 JSON 模板（含示例）](../templates/basic-style-candidates-example.json)，从识别请求复制作品 ID、名称、简介和来源。将 `model` 填为实际使用的模型名称，在 `candidates` 中填写维度代码、标签、原文摘录和来源；没有待补资料时保留 `issues: []`。页面校验候选维度、词表、简介摘录及现有来源。勾选候选可逐项或整批预览，确认后追加所选标签并保持每部最多六个，每个标签单独记录模型、摘录和来源。审核前可退回候选，待审队列保存在当前浏览器。

## 主作品与关联版本

勾选至少两部作品，点击“合并所选作品”，选择主作品。其他记录在独立列表中收起，保留原名称、年份、玩法、来源与身份，在主作品编辑窗口显示为关联版本；按版本名或别名搜索仍可找到主作品。已有的下属版本一起归入所选主作品。打开版本可以继续修改、删除或解除合并。

默认“内容关系待核”，只建立基础库归组关系。已核实的相同内容或新增内容必须填写具体比较依据和来源。普通移植、译版、再版等不能自动视为新增内容。基础库归组不直接生成正式主库 `contentVersions` 或平台发行，也不改写原始完整档案与历史署名；提升正式主库仍需核实原作及新增内容的首批证据。


## 保存时提示权限错误

目标仓库是 `wt1234-donkey/visual-novel`。先使用有该仓库权限的账号登录 GitHub，再创建 Fine-grained personal access token：Resource owner 为 `wt1234-donkey`；Repository access 为 `Only select repositories` 并勾选 `visual-novel`；Repository permissions 中 `Contents` 为 `Read and write`。选择 `Public repositories` 仅包含公开仓库读取权限，不足以合并或修改作品。页面的创建凭证链接会预填资源所有者与所需权限，生成前仍须核对仓库选择。

公开仓库的读取成功不能证明凭证有写入权限。页面会分别提示账号无写权限、凭证无效、内容写入被拒、请求频率限制、文件读取失败、并发冲突或分支规则拒绝；保留当前合并选择和说明。更正凭证后在同一窗口重新连接并保存。不要把凭证发到聊天。

## 网页加载与本地预览

发布时生成轻量检索索引和按默认年份顺序分片的详情文件。首页默认读取统计和当前页分片，输入关键词时再读取基础作品检索索引。基础身份库读取轻量筛选索引，翻页后按需读取该页分片。编辑、标签写入及 AI 候选资料读取按所选作品加载。大范围检索可在浏览器后台线程执行。页面中的原始 JSON 链接供查阅和离线核对。

本地预览使用与 GitHub Pages 一致的构建流程。在仓库根目录运行 `python3 scripts/build_pages_artifact.py --output _site`，再从 `_site` 启动静态服务。构建需要 Node.js 20 或更新版本。

## 统一送审与发布

基础身份库、正式作品、资料管理台和批量补录均可从网页把更改送入[编目审核台](https://story-atlas-editorial.wwangtao833.chatgpt.site)。提交前可查看修改前后、来源链接及实际将执行的操作。审核台初始仅供所有者访问。协作者先由所有者邀请访问审核台，再以其登录邮箱分配编辑者、审核者或发布者角色。编辑者只查看自己的提案；审核者可批准或退回待审提案并填写证据核实说明；发布者可批量发布已批准的提案。

发布流程由 GitHub Actions 在主分支最新资料上重跑原有校验。遇到重复身份、目标修订变化或并发提交时，批次停止写入，请重新读取相应作品并提交新的提案。审核记录保留核实时间、说明和发布运行链接。每批最多 20 条提案，总大小不超过 55 KB。

自动发布需在审核台服务器配置 `EDITORIAL_GITHUB_TOKEN`。该专用凭据仅选择 `wt1234-donkey/visual-novel`，仓库权限设置为 `Actions: Read and write`，用于触发并查询发布工作流。GitHub Actions 使用自己的令牌提交数据和触发 Pages。普通编辑者使用审核台登录即可。配置前，提案录入、提交和审核可照常进行；批准的提案保留在队列中。
