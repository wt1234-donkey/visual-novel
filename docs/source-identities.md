# 来源、作品身份与待核案件（A07）

四类对象分别管理：原始来源记录（权威登记中的原对象）、稳定作品身份、来源→作品的显式身份链接、身份待核案件。适配层 `src/domain/catalogue/source-identities.mjs` 保留原记录引用，数据索引由 `build_source_identity_index.mjs` 派生；唯一新增的人工状态文件是 `data/source-identity-decisions.json`。原有作品、内容版本、发行、原始证据和来源顺序不改写。

迁移基线：108,173 条权威源记录，109 个原始分片；基础索引兼容显示108,269组（含103条旧索引来源，5条删除，2条子关系），批量入口108,166组；发现页基础投影107,025行；正式主库与补充档案1,662条。上述口径不同，均不得称作“已核独立作品总数”。身份清单108,968条含暂定和旧索引身份；继承明示ID对应1,902个不同目标，新显式核对目标0个；其余106,271条权威来源对应未核。候选3,388件涉及6,342条已准入来源，另保留未准入的历史案件证据。候选数和来源数不能相加。

同名同年（含别名）只产生候选，链接沿用原稳定ID。共享URL或外部引用也不能自动复用作品。批量补档案时，只有明示 linkedRecordId、basicRegistryId 或显式确认的身份链接才能复用档案；名称和来源引用碰撞留待核对。明确判为独立的案件仅放行该次结论覆盖的冲突身份，不能全局跳过查重。未来参数化来源批次继续保留原来源对象，记录为 unreviewed；同一外部来源ID和年份的重复采集仅计作重复来源观察，不是作品合并。

正式补档案沿用来源原作品身份，保留新正式档案ID作为 profileIds 映射。二者不同不产生第二部作品，也不把新增档案当作新增权威来源。显式身份核对不会推断内容版本关系、删除来源或自动修改旧基础索引的兼容父子归组。

`source-identities.html` 分页显示四类对象和各自统计，名称/别名精确检索或按原ID定位。打开页面和切换目录不下载全部109个源分片；只有“完整原记录”读取选中来源所在的一个分片。索引、决策和原文绑定同一发布版本，使用摘要校验、超时和取消。统计标明发布版修订，已保存未部署的结论另显示最新日志修订。

直接保存沿用可信命令执行端，不新增人工发布审核。每次结论包含操作ID、操作人、时间、理由、来源URL、前后值及案件成员范围；同一/不同身份的整案结论必须覆盖所有来源，超过500条时需分条或分批核对。旧未准入案件不伪造来源，只可暂缓或不准入结案。新增来源或候选改变案件范围时重新标为待核，既有显式链接保留。不得重置日志、剪掉旧事件或直接修改当前链接快照。

撤销追加独立逆向事件，保留被撤销记录；如同一链接或案件在此后已有核对（包括重新确认同一目标），拒绝旧撤销覆盖后续结论。响应中断后，sessionStorage 仅保留不含凭证的原命令（原ID、时间、来源租约和修订）；重试先查统一回执，已执行则只确认原操作，保留后来事件。未执行的过期命令必须重新读取后形成新操作。凭证只留页面内存。

运行 `node scripts/migrate_source_identities.mjs --check` 验证原始108,173条完整对象的有序摘要、日志回放、稳定ID引用和迁移投影。基线禁止重置，允许在原前缀之后追加来源。完整检查与 Chromium 网页检查分别使用 `python3 scripts/validate_catalogue.py` 和 `node --test tests/browser/*.test.mjs`；测试核对事件只存在临时数据，生产初始日志保持空白。
