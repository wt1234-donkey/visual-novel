# 统一写入、回执与归档边界

所有活跃资料写入先在隔离工作区形成候选，使用同一封存协议，再运行 `scripts/validate_catalogue.py`，最后由既有受保护提交／PR入口推进。个人保存不增加人工审核。`config/write-entrypoints.json` 登记全部 Contents 写入工作流；Pages 的 Contents 权限仅用于派发。新写入入口遗漏登记、共同校验或封存调用时，流程治理检查失败。

|入口|领域应用|回执与封存|提交范围|
|---|---|---|---|
|个人基础／正式／身份／字段|共同命令规划器、来源租约、修订、不可变操作ID|领域事件、command-receipts、共同归档封存|既有可信数据提交，禁止强推|
|旧编目批次|基础与正式提案转为共同命令，复用选用字段及冲突规则；批次仍校验完整摘要|逐项命令回执和批次回执；一次归档封存绑定全部子操作|既有已校验数据提交|
|管理更新包|保留管理领域规则、前值与管理历史|按完整包摘要定位回执；重试先确认原回执，保留后续修改|独立候选分支|
|参数化来源补录|保留来源快照、计划摘要、去重／隔离规则和原ID|批次ID及完整计划绑定回执；共同封存|独立候选分支|
|隔离保存演练|复用个人命令及封存器|相同回执协议|专用隔离分支，main不写测试资料|

`src/infrastructure/filesystem/write-boundary.mjs` 生成或核对归档，核对领域回执与事件身份，给新回执附加不可变归档根，并再次严格检查。批次封存核对全部领域子操作。`seal_catalogue_write.mjs` 为Python和旧同步脚本提供同一入口；不接受远程代码、仓库或Git目标参数，不推广分支。

共同验证在任何派生生成之前先严格检查当前归档及新回执，避免通过打包时临时重建掩盖源码提交中陈旧索引。已封存回执必须指向当前源码归档代次链中的根；重复确认不改写原回执。迁移前的回执原样保留，未补造旧证明。完整Git提交同时保存资料、日志、回执、归档入口及新增对象；未通过共同验证的工作区不得推广。

网络连接及响应正文均有单次截止时间；命令等待另有可取消总预算。响应不确定时沿用原操作ID。只有确认终止失败、重新读取main仍无原子回执，才将命令标为明确未应用，允许同步后重新校验。发布状态的失败比较缓存会淘汰，后续检查可以恢复。

当前显示生成包括专题、CSV、分类、组织与关系目录，读取同一有效投影；原始作品、发行署名、身份与历史审核记录不改写。组织目录加入同一发布的冻结资源。生成产物和可信写入始终使用当前来源，但不将显示订正复制回原始事实。
