# Repository and editorial rules

- All `visual-novel` changes, additions, pull requests, merges and Pages releases target **wt1234-donkey/visual-novel**. Do not write to `wwangtao833-dev/visual-novel` or synchronize changes back there.
- Read `data/content-model.md` before editing catalogue data. Schema v2 separates `works`, `contentVersions` and `platformReleases`. The old `versions` array must not be reintroduced, including inside related games.
- Preserve work identity, historical platform credits and source evidence. Existing historical releases with unknown content relationships stay `unverified`, with `contentVersionId: null`; do not equate unknown with identical or newly added content.
- A new work needs one original content record. A later content version requires specific, sourced additions and a comparison content ID. New story, character/route, playable area, art, music or recordings may qualify. Ordinary ports, translations, reissues, package changes, compatibility fixes and resolution increases alone do not.
- Future additions record only the first release batch of original/new content (`releaseRole: contentDebut`). Multiple platforms in that same batch reference ONE content ID. Do not append ordinary later ports just to expand the platform list.
- Leave the existing genre/command-game exceptions and historical publisher attribution in place.
- Regenerate both CSV indexes and dossiers. Required checks: `python3 scripts/validate_data.py`, `python3 -m unittest discover -s tests -p 'test_*.py'`, `node --test tests/*.test.mjs`, and `python3 scripts/build_company_pages.py --check`.
- Every main and related work must have nonempty `interactionModes`, `interactionNote`, `interactionBasis` and `interactionSources`; use the controlled labels in `taxonomy.interactionModes`. Read `data/interaction-model.md`. Assign multiple documented controls when needed, distinguish parser input / action menus / story choices / scene hotspots, and never infer playable combat from a battle-themed plot. Use the explicit `待核实` state if controls are unknown. Tags summarize known work-level play modes and must not be presented as uniform across all ports.
- After interaction edits run `python3 scripts/export_interaction_csv.py`, regenerate the other indexes and company pages, and keep the source/basis attached. Preserve the content-only future admission rule.
- New company dossiers use verified establishment dates after 1949, prioritizing companies already represented by actual catalogue releases without an existing dossier. New dossiers focus on narrative games and RPGs; do not expand them with pure daily-life training/raising, mahjong, board-game or pure competitive titles. Keep already published historical exceptions in older dossiers.

- FairyTale专题按2026-10-19用户要求允许文字输入叙事；既有主库身份复用。此具名例外不自动扩展到其他品牌；资料不明仍需核实，不能仅凭ADV标签判定独立叙事。

- Konami专题按2026-10-19用户要求允许文字输入叙事进入主库；复用旧作品身份，不将起名／存档名／一次性密码误记为解析器，也不自动改变其他厂商的具名例外范围。

- Entity/participation migration: read `data/entity-model.md` before changing company, brand, developer, publisher or dossier relationships. Preserve original `publisher`, legacy publisher indexes and shared work/content/release identities. New scoped credits, entity identities and dossier membership live in the additive indexes generated by `scripts/build_entity_model.py`; do not infer a developer from a publisher or copyright signature. Keep unresolved identities/roles explicit.
- After changing entity rules or catalogue membership regenerate `build_entity_model.py`, `build_entity_pages.py` and `build_company_pages.py`; run `validate_entity_model.py` plus all existing checks and all three generators with `--check`. The entity migration baseline allows appended identities but protects existing objects; historical corrections need separate sourced review rather than silently rebasing. Keep all prior dossier URLs/anchors and five-year navigation semantics.
- Japanese entity display names use English/Latin spelling（日文）. Maintain `data/entity-display-names.json`, including transliteration/translation basis; regenerate the entity indexes and pages. Apply display names only after resolving historical credits. Preserve raw publisher fields, legacy filter values, entity IDs and old search aliases; a shared display label must never merge identities.
